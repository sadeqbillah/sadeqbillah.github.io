Universal Surveillance Interface: Sentec Bridge

Developed and commercialized the Sentec Bridge Unified Device Controller, a middleware platform that integrates diverse IoT sensors and devices into a single communication channel. The system unified manufacturer APIs through a common interface, enabling seamless interoperability, simplified device onboarding, and centralized control of input and output services.

Unified Device Controller IoT Integration Platform MQTT REST APIs SQL Server PostgreSQL Windows Service Sensor Control Device Interoperability Middleware

Project Description

We designed and implemented a unified communication framework that standardized how heterogeneous IoT devices interact with surveillance and monitoring systems. Input controller services (face detection, fingerprint, weather, fire, sound anomaly sensors, smart cameras, PTZ rigs, and edge computing devices) were connected through a WCF‑based middleware supporting both REST (HTTP) and MQTT protocols. This ensured consistent data reporting, configuration management, and control commands regardless of the underlying device API.

Key Features Delivered:
  • Unified manufacturer APIs into one channel
  • Common interface for diverse sensor controllers with standardized methods
  • Plug‑and‑play support for new devices following integration guidelines
  • Input services: face detection, fingerprint, weather, fire, sound anomaly, smart cameras, PTZ rigs, edge computing devices
  • Output services: LED screens, sirens, loudspeakers, alarms, SMS, email notifications
  • Centralized data reporting, configuration, and control via WCF (REST/MQTT layers)
  • Database integration for structured storage and retrieval (SQL Server/PostgreSQL)

This architecture allowed new IoT services to be added seamlessly, while ensuring interoperability between input sensors and output actuators. Operators could configure alarms, notifications, and device actions through a unified interface, reducing complexity and improving scalability.

Tools & Technologies

The system was implemented using Windows Services with WCF as the communication backbone. REST (HTTP) and MQTT layers enabled flexible data exchange between devices and the central controller. SQL Server Enterprise and PostgreSQL provided robust database support for sensor data, configuration, and control logs. The architecture emphasized extensibility, interoperability, and certification compliance, ensuring that new devices could be integrated with minimal effort.
